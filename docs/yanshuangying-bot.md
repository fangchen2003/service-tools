# 燕双鹰 · 违规公示 bot（设计稿，未实现）

站长 10/11 提出：单独做一个「封号警告类的威武 bot」，名字用「燕双鹰」。奶妹继续当贴心助理，燕双鹰只管违规处罚的告知。

## 定位

| | 奶妹 | 燕双鹰 |
|---|---|---|
| 语气 | 贴心、可爱 | 冷峻、简短、威武 |
| 职责 | 领 Key、额度、反馈、公告 | 只播报处罚结果 |
| 私信 | 关（总开关） | **不发私信** |
| 斜杠命令 | /register 等 | 无（只说话，不接命令） |

## 需要站长做的（我不能代办：涉及新建账号和密钥）

1. Discord 开发者后台 → New Application，名称「燕双鹰」→ Bot → Reset Token。
2. 头像：剪影、徽章或鹰的图案；不要用演员照片（肖像权）。
3. 邀请链接只勾 `bot`，权限只给 **Send Messages、Embed Links**（权限值 18432）。不开任何特权 Intent。
4. 把 Token 写进服务器 `/opt/service-tools/.env`：`WARDEN_BOT_TOKEN=...`（自己在服务器上写，不要发在聊天里）。
5. 建一个频道「⚠ 违规公示」，成员只读，燕双鹰可发言；把频道 ID 告诉我。

## 触发与内容

数据来源全是网关里已有的处罚事件，燕双鹰只是换个嘴说出来：

| 事件 | 来源 | 公示内容（示例） |
|---|---|---|
| 防分享暂停 | share_guard `paused` | 「编号 #A3F 的 Key 检测到多人共用，暂停 24 小时。一人一 Key，规矩不变。」 |
| 撤销 Key | 后台 / `/revoke` | 「编号 #A3F 的 Key 已撤销。原因：转卖。」 |
| 封禁领取 | `/ban` | 「一名成员因违规被永久禁止领取。」 |
| 解除 | 暂停到期 / `/unban` | 不公示（避免二次曝光） |

原则：
- **不 @ 当事人、不写用户名**，只给 Key 的短编号（成员自己能在 /quota 里看到自己的编号）。不公开证据细节（IP、设备、提示词）。
- 每条一句话，带一行固定落款：「—— 燕双鹰」。
- 同一事件只发一次；每小时最多 6 条，超过合并成一条「本小时另有 N 起处理」。
- 只有自动处罚确定生效后才发；`observe` 模式下的模块（只记录不执行）不发。

## 实现（站长给 Token 后约半小时）

- 用同一个镜像，在 `docker-compose.yml` 里加一个 `warden` 服务（profile `discord`），入口 `integration/warden_bot.py`。
- 不连 Gateway 事件（零 Intent），只用 REST 发消息：每 30 秒向网关桥接接口 `/self-register/warden/events` 拉一次待发事件（走现有的 `REGISTRATION_BRIDGE_SECRET`）。
- 网关侧新增表 `warden_queue(id, ts, kind, key_short, text, sent_at)`；share_guard / admin revoke / ban 在执行处罚时写入一行。
- 后台「Discord」页加开关：燕双鹰 开 / 关 / 只记录不发。

## 风险与边界

- 新应用的封号风险：只在一个频道低频发言、零私信、零 Intent，属于最干净的用法。
- 误判：防分享有误报可能，所以首周用「只记录不发」模式跑，站长看过公示草稿再切到「发」。
- 评估周：燕双鹰不改任何额度和处罚规则，只是播报，不影响算法数据。
