## 二、风控风险（按严重度）
- **R1 单账号共享 = NovelAI ToS 风险（结构性）**：47 人一个 Opus 订阅、多网段。无法消除，只能靠"好公民"策略（每小时上限、出图间隔抖动、日 V5 压在订阅真实上限之下）降低被上游检测概率。
- **R2 防分享没执行、且现实的 VPN 轮换根本不计分**：`share_guard_mode=observe`；评分只在"换网段 + 换客户端指纹"同时发生才算，单 UA 顺序切 VPN 不计分。结果：吉吉子(key7)、kfzbrlm(key14) 各 **8 个 /24 网段**却得 0 分；唯一有分的是 10 个合成对照 Key。→ **分享/转卖目前既没被处置、现实情况也没被计分**。
- **R3 客户端重试风暴**：哈哈哈大王 112 请求 **86 被拒(77%)**，死循环无视 402/429。全部**本地挡下**没打到上游，但 `key_guard`（拒绝 1h≥60 → 停 1h）是 observe，没自动节流。
- **R4 Discord 再被封的残余风险**：三项整改已核实在代码里（intents 清零、scope=identify、/issue 直发不私信、画廊自动化关、message_content 去掉）。**残余**：网页 OAuth 登录仍在发生（窗口内 8+ 次）+ 领 Key 聚集，短时间再来一波授权突增仍可能重触发 680009。**申诉期间尤其敏感**。
- **R5 隐私/留存**：`generation_audit` 存了**全体成员的完整提示词 + 原图**（603 行、原图 155MB）；`audit_retention_days=0` = 提示词**永久保留**，原图约 3 天。集中存所有人作品是机密 + 磁盘风险（DB 已 166MB）。
- **R6 自对账一次性报错**：02:26:52 容量交叉校验抛过一次 ProgrammingError，**之后再没出现**（每 10 分钟一轮都正常）→ 判定为重启时的瞬时竞态，非常驻 bug。
- **R7 额度电池不自愈**：04:10–04:29 站长手动给 28/7/56 重置额度，算法没自动给重度用户放量。

## 三、全系统总结：哪些真由算法安排，哪些还没
**已完全自动且在生效（需求塑形层）**：动态额度电池（V5 剩余+恢复，按活跃人数切，每人 18/天）、AIMD 每小时上限微调、每小时固定窗口+空闲借用、M/D/1 排队（并发 1、间隔 15s+抖动）、每请求 429 冷却 60s、Anlas 续杯、nai-watch 异常监控。窗口内都在正常工作。
**已建好但停在 observe / 还手动（防御执行层）**：
- 防分享执行（observe，且未校准）——**R2**
- 全站熔断 5 分钟（observe，只有 60s 冷却是自动的）——**U2**
- 重试风暴/滥用 Key 自动停（key_guard observe）——**R3**
- 闲置回收 / 自动扩名额（observe）
- **DRR 公平调度没启用，当前是纯 FIFO**（`live.mode=fifo`）
- 重置点算法建议 12:00（最闲）但仍硬编码 00:00
- 重度用户额度自救（靠手动重置）——**R7**

> 一句话：**"塑形"已经算法化且好用；"防御/执行"都建好了但停在观察档**，所以最关乎"别再被封"的那些动作目前还靠站长手动。

## 四、预案（优先自动，分期）
**A. 现在就该上（降低被封信号、低误伤）**：
1. `key_guard` → enforce（仅"拒绝1h≥60 停1h"这条）：自动掐重试风暴。
2. 熔断 → enforce：上游 5xx 成簇时自动全站停 5 分钟。
3. 流式失败**有界自动重试**（首图产出前失败才重试、带抖动退避）+ 失败 V5 **自动退还**（依赖对账）。
4. **新 OAuth 登录/领 Key 每小时限速**：把当初触发 680009 的"授权突增曲线"抹平；申诉期间尤其该加。
5. `audit_retention_days` 设有限值（如 7/14 天）；考虑提示词只存哈希、原图可选不存。
**B. 校准后再上**：防分享用 `req_features`/`share_evidence` 回测定阈值，先开 warn(≥30) 档；补一个"单 Key 24h 内 /24 网段数 > N 就告警站长"的廉价信号（吉吉子、kfzbrlm 会触发）。
**C. 常规**：DRR 挤时自动切换（冻结期后）；重置点改 12:00。

## 五、顺带：关于"接入大模型的 bot"
想要的那类（如 Odysseia-Guidance）= LLM 聊天 + **读消息** + **新帖自动评论** + 自动引导——**正是把我们封掉的行为**（需要 message_content 特权 + 自动 AI 互动）。**申诉通过前绝对不碰**；即使以后要做，也应：年龄门/opt-in、严格限频、可一键关、与"发 Key"职责分离。我们现在的奶妹是**确定性发 Key**（一条命令→Key，不读消息、不 AI），这正是它"干净"、好过审的原因。
